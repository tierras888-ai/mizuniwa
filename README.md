# 水庭 MIZUNIWA

ブラウザの中に、小さな水庭を。真上から眺めるメダカと睡蓮の、静かな水庭です
V1の仕様は添付された `mizuniwa_prompt_v2.md` のみを基準にしています。

## 起動

依存ライブラリ、インストール、ビルドは不要です。

```sh
cd /workspace/mizuniwa
python3 -m http.server 8000 --bind 0.0.0.0
```

ブラウザでサーバーのルートを開きます。`index.html` を直接開くこともできますが、保存領域が安定するHTTPでの利用を推奨します。同じブラウザ・同じオリジンに保存されるため、ポートやホストを変えると別の水庭になります。

## 技術

Canvas 2Dを採用しました。低解像度の波高マップとオフスクリーン描画による微小な屈折で、外部素材・GPU依存なしに軽く動く水面を作るためです。
砂利、植物、魚、石や木の質感、花、光はすべてコードで手続き生成します。外部画像・CDN・フォントへのアクセスはありません。

80×56の減衰付き波高マップで入力を伝え、水中シーンを小さな領域ごとにずらして描画します。クリックでは3つの円形波面の近くをさらに再サンプリングし、水底・水草・メダカ自体の屈折を表現します。画面全体に時間帯の色を重ねず、空の色は局所的な反射帯へ限定します。夜はRGB共通の照度を落として、元の色相と視認性を保ちます。水底→オブジェクト・水中植物→魚と影→屈折→反射と光→浮葉・花→UIの順です。植物とオブジェクトは生成画像をキャッシュし、植物は回転でゆっくり揺らします。
DPRは2以下、描画バッファは最大960×820の範囲に収め、フレームが遅い場合は屈折の分割数を落とします。タブ非表示時は停止し、`prefers-reduced-motion`では揺れと遊泳を弱めます。

## 操作

- 水面をなぞると繊細に揺れ、触れると波紋が広がります。近くのメダカは少し逃げます。
- メダカに触れると、名前・性別・月齢・体色・性格が数秒表示されます。名前欄を編集できます。
- `◌`：餌モード。水面に触れて餌を落とします。もう一度押すと終了します。
- `✧`：水草とオブジェクトを追加。候補を選んで水面に触れる、または候補から直接ドラッグします。
- 配置済みのものは編集モードで選択。ドラッグ、回転・大きさのスライダー、削除が使えます。パネルが重なる場合は「移動する」でパネルを隠します。
- `⋯`：設定。時間帯と水底（砂と小石・玉砂利・砂地）の変更、確認付きの「水庭をリセット」。
- `◇`：鑑賞モード。すべてのUIを隠します。右下65px以内へのタップ、またはEscで戻ります。
- Esc：メニューを閉じる。すべてのボタン・名前欄・スライダーはキーボードでも操作できます。

水草は睡蓮・マツモ・アナカリス・浮草。オブジェクトは丸石・苔石・流木・陶器の壺・石灯籠・小さな橋・竹・小さな鳥居。水草とオブジェクトは合計100個までです。スマホは1本指で移動し、回転と拡大縮小はスライダーで行います。

## 時刻・保存

ブラウザの現地時刻で朝（5–10時）、昼（10–16時）、夕（16–19時）、夜を切り替えます。設定から固定することもできます。
動作確認用の `?time=morning` / `day` / `evening` / `night` は保存設定を変更せず、そのページの光だけを固定します。

`localStorage`の `mizuniwa.garden.v1` に、`version: 1`、メダカの全個体情報、水草、オブジェクト、配置・回転・サイズ、時間・水底設定を保存します。座標は0〜1です。変更時、5秒ごと、タブ非表示・ページ終了時に保存します。
リセットは初回起動と共通のデフォルト生成処理を使い、水底、全配置、個体情報、時間設定、餌、波高マップを初期化して保存データを上書きします。水底項目のない旧V1保存は、そのほかの内容を維持して読み込めます。

未知のバージョン、破損・不正なデータは初期状態へ復帰します。保存禁止・容量不足でも鑑賞と操作は継続します。魚の繁殖・年齢進行・季節による変化はV1に含めていません。

## テストの再実行

アプリの実行依存とは別に、開発用のPlaywrightとChromiumが必要です。このクラウド環境には両方が用意されています。

```sh
node tests/acceptance.cjs
node tests/water-reset.cjs
```

テスト自身が一時HTTPサーバーを起動・終了します。別環境では、既存のPlaywrightモジュールへのパスを `PLAYWRIGHT_MODULE`、Chromium実行ファイルを `BROWSER_EXECUTABLE`、テストポートを `TEST_PORT` に設定できます。例：

```sh
PLAYWRIGHT_MODULE=/tmp/mizuniwa-tests/node_modules/playwright \
BROWSER_EXECUTABLE=/usr/bin/chromium node tests/acceptance.cjs
```

`artifacts/test-report.json` に各確認の結果、fps、フレーム時間、コンソール出力を記録し、昼・夕・夜、鑑賞モード、横向きのPNGを保存します。実機スマホのfpsとSafari互換性は別途実機で確認が必要です。

## 次バージョンへの拡張

- **繁殖・成長**：個体の `id`、性別、月齢を基準に更新フックへ追加。保存スキーマの次バージョンと明示的な移行を実装します。
- **季節**：`seasonLayers.under` / `seasonLayers.over` に描画を登録できます。V1では空で、季節イベントは動作しません。
- **図鑑**：個体の体色・性格と植物／オブジェクト種別を参照します。
- **観察日記**：名前変更・摂食・配置などのイベントに日時と個体IDを付けて記録する設計へ拡張できます。


## 単一HTMLの書き出し

配布用には、CSSとJavaScriptをすべて埋め込んだHTMLを生成できます。アプリを動かすためのビルドではありません。

```sh
python3 scripts/export-standalone.py artifacts/MIZUNIWA.html
```

`tests/water-reset.cjs` は水底2種類それぞれについて編集→確認付きリセット→再読み込みをPCと375px画面で検証し、水底のPNG画素が初期状態と一致することも確認します。画像・結果は `artifacts/water-reset-report.json` と `*-clear-*.png` に記録します。

## GitHub Pagesで公開する

公開用の `index.html`、`style.css`、JavaScriptはリポジトリのルートにあります。パスはすべて相対指定なので、GitHub Pagesの `/mizuniwa/` 配下で動きます。`.nojekyll` により、そのまま静的ファイルとして配信します。ビルドやActionsワークフローの追加は不要です。

GitHubのリポジトリ設定で以下を選択します。

1. **Settings → Pages** を開く。
2. **Build and deployment → Source** を **Deploy from a branch** にする。
3. **Branch** を **main**、フォルダーを **/ (root)** にして **Save** を押す。

デプロイ完了後、Pages設定に表示される公開URLを開きます。初回の配信には数分かかることがあります。公開先は開発サーバーと別のオリジンなので、開発中のlocalStorageは引き継がれません。
